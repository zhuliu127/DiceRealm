二、根因取证 / 旧版对齐 / 关键决策
---------------------------------------------------------------
【规则真值（自己核实，不猜）】
  `lib/domain/rules_coc7.dart:122-124`：genMin=15 / genMax=90 / genStep=5。
  `genRandomDice`（:126-138）9 项齐全：str/con/dex/app/pow/luck=3D6，
  siz/int/edu=2D6+6，结果统一 ×5。
  旧版 `core/ai.js#applyAttrCap` 用 ATTR_MIN=15 / ATTR_MAX=99，
  生产新算法上界取 `_floorToStep(genMax)=90`（不再是 99）。
  `lib/ui/create/chargen_logic.dart:26-33 attrFieldError` 才是卡死点：
  `v % genStep != 0` → 「必须是 5 的倍数」→ `checkAttributes` 报错
  → 进 `CreateFlowPage` 后无法点下一步。根因链与派工取证一致。

【A 的不变式（写进 `ai_caps.dart` 源码注释）】
  I1 未超限（sum <= attrCap）→ 返回 false，属性一个字节都不改。
  I2 超限 → 每个输出值 `v % genStep == 0`。
  I3 超限 → `genMin <= v <= genMax`。
  I4 超限 → 总和 `total <= attrCap`（宁可略低于上限，绝不因取整反弹；
      余数按 5 步长分配，不足一步的零头丢弃）。
  I5 相对高低不乱：按原始值降序排好后输出值非增（相邻倒置交换，
      交换不改总和、不改 5 倍数）。
  I6 withLuck 两种口径只对参与求和的 keys 生效，未参与求和的项不动。
  ★ 物理下界如实说明：total 最小 = keys.length × genMin
    （9 项 = 135 / 8 项 = 120）。attrCap 低于它时 I3 与 I4 无法同时
    成立，算法优先 I3（规则区间），全项压到 genMin 并停止扣减，
    返回 true（确实动过）。调用方不会拿到非法属性。

【决策 1 · 有意偏离旧版压缩算法（必须让 QA 知道）】
  依据用户 2026-11-10 真机反馈：旧版 JS `core/ai.js` 的
  `applyAttrCap` 也是非 5 倍数，改成 5 倍数是**有意偏离旧版**。
  取舍采用派工给的 ② 方案：**保留一个「原始算法」专供预言机、
  生产走新算法**，不悄悄改 fixture 让测试变绿。
    · `applyAttrCapLegacy` 一行未改地复刻旧 JS（等比 + floor +
      最大余数 +1 + 超限从最高项 -1 + 相邻倒置交换）。
    · 开关只在 `test/oracle_preset_test.dart` 的 setUp 置 true、
      tearDown 恢复；其它全部测试与生产默认 false。
    · `test/fixtures/preset.json`（4,541,338 字节，mtime 11-08 14:55）
      与 `qa_p3_ai_oracle.json` 等冻结 fixture **一个字节未改**。
    · 影响面：`qa_p4_gate.js` 是静态探针（不比对 cap 输出），
      复跑 13/13 全过；`oracle_preset_test.dart` 仍逐字段比对冻结
      fixture 且全过；`qa_p4_fresh_oracle.js` 属房间模型预言机、
      与本算法无关。**P4 冻结基线零影响**。
    · 唯一需要留意的情形：将来若有人用「生产算法」重新生成
      preset fixture 里的 caps 用例，期望值会变（那是有意偏离，
      届时需同步基线并写明依据，不能悄悄改）。

【决策 2 · attrsFromAi 选「拒收走重掷」而不是「就地规整」】
  ① 外部输入闸门，拒收最保守：规则层随后用 `genRandom()` 重掷，
     一定是 5 倍数且落在规则区间；
  ② 就地规整会篡改 AI 配好的人物性格，且与 `applyAttrCap` 的
     5 倍数网格形成「第二套规整实现」，违反单一真源；
  ③ 压缩路径负责「超限」、闸门负责「未超限」，两者合起来
     覆盖两种情况，绝不让非法值进卡。
  顺带把旧的宽松区间 15–99 收紧为规则真值 15–90，并对 luck 同样
  要求 5 倍数（旧口径只看 8 项、luck 只要能 parse）。

【决策 3 · B 的测试环境硬约束（铁律 T1）】

  所以做成可注入 port（同步 void + `unawaited`），测试注入同步
  计数替身，widget 里零 await。与既有 `RoomHistoryExportPort` 同款。
  **平台边界如实说明**：生产落盘是「发起即返回、不等待」，
  失败只记 `SettingsRepo.lastError`，不阻塞上屏反馈；本批未验证
  真机文件系统行为（属真机待测）。
