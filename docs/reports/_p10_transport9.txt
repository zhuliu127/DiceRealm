■ ① 横屏网格重排（核心） —— lib/ui/room/widgets/room_layout.dart
  真因（几何实测推导，非纸面）：
    · 1280dp 档：内容宽 1256，左栏 17% ≈ 213dp。左窄栏素材行是
      「素材名 + 隐藏/封面/删除」固定 Row，需 ≈ 266dp → 溢出 53px，
      被 `_slotView` 的 tooNarrow 横向滚动 + ClipRect 兜底 → 用户截图
      「素材 隐藏 封面 删除 右半边被裁」。
    · 舞台：Material 舞台已用 AspectRatio(16:9)，但上排 60% 让 map 格
      高 ≈ 402dp，而 16:9 高只有 ≈ 248dp → 格内上下各留 ~77dp 空白 →
      用户「中间一大片空白」。且 `GpMapStage` 原本**没有渲染素材图**
      （只画笔迹/标点），assets 非空时也是一片灰。
  改动：
    · flex：上排 60→44、中排 34→41、状态 6→5；上排内 工具 30→24 /
      素材 43→50 / 右列 27→26（舞台加宽，压掉舞台留边；底部三块拿更多高度）。
    · roomDockMinWidthOf：gpKpTools 280→240、gpKpLeft 230→200
      （左栏素材行改两行后 213 够用，且不再触发 tooNarrow 横向滚动）。
    · 保留硬约束：根 17/83 三层、10 槽 DFS 顺序、gpKpLeft[17]、
      gpKpTools.first==83、gpMap.length==3（p10_t3 全绿）。
  证据：p10_t6_layout C1（新 flex 期望值已同步）、C3[1280/1524] 全绿；
        p10_t7 T1 断言「相邻格间距 == 8、底部三块等高、10 格夹在
        顶栏~工具栏之间、零 RenderFlex overflow」。

■ ② 亮色主题栏位标题看不见 —— lib/ui/room/widgets/room_panel_kit.dart
  真因：`_textTheme()`（lib/theme.dart:218）**没有定义 titleSmall**，
  `SectionBox` 直接用 `textTheme.titleSmall` → 回落到 DefaultTextStyle，
  亮色皮肤下与卡片浅底几乎同色。
  改动：标题 style 改为 `copyWith(color: Theme.of(context).colorScheme.onSurface)`
  （亮=深墨、暗=浅墨；onSurface == Palette.text）。
  证据：p10_t7 T2 亮暗两套断言「标题色 == onSurface 且与 cardColor
  亮度差 > 0.45」。

■ ③ 顶栏去重 —— lib/ui/room/widgets/gp_topbar.dart
  真因：身份行 `whoLine` 已含「KP·KP 主持」，另外又单独渲染一个
  「角色：主持人」胶囊；KP 还多一行「服务：本机进程内（未联网）」。
  改动：删掉 `角色：…` 胶囊与整块 KP service 行（`_oneLine` / `_twoLine`
  两档同时删；`_TopbarData` 对应字段一并移除）。两个 key 常量保留，
  注释标明「已撤渲染，供反向断言，不代表还有 UI 在用」。
  口径更新（保留语义、加正向「旧的必须消失」断言，不删用例/skip）：
    · test/room_ui_shell_test.dart：role/service 由 findsOneWidget 改
      findsNothing（并保留 who 仍在的断言）；service 用例改名
      「服务地址块已整体撤除（三种视角都不再建）」。
    · test/p10_t6_layout_test.dart `_topbarKeys()`：移除 role/service
      （否则 getRect 落空）。
  证据：p10_t7 T4 反向断言 role/service findsNothing 且 who 仍在。

■ ④ 两个栏位整合（素材管理只留一处） —— gp_kp_tools.dart + gp_kp_left.dart
  真因：第二列（工具窄栏）与左窄栏「素材」tab 各有一份「未公开素材 +
  上传 + 隐藏/删除」（用户图 2 / 图 3 两套）。
  改动：
    · gp_kp_tools：删掉「未公开素材」列表 + 逐素材 隐藏/删除 + `assets`
      变量；只保留一个「上传素材」功能入口（`GpKpToolsKeys.upload`
      保留 → qa_p5_priv_probe 的 asset.add 探针继续有效）。
    · gp_kp_left：素材行由「名字 + 3 按钮」固定 Row 改「名字一行 +
      按钮 Wrap」（48×48 热区不变、完整落在格内、不再被裁）。
  证据：p10_t7 T5 左栏素材 tab 仍可见「旧地图 + 上传」；
        room_ui_kp 用例改为「上传走工具窄栏 / 公开·删除在左窄栏素材 tab」全绿。

■ ⑤ 公开素材严格 16:9 —— gp_map_stage.dart + room_game_page.dart
  真因：`AspectRatio(16/9)` 已存在（RoomTheme.mapAspect=16/9），但 (a)
  格子过高，16:9 舞台在格内上下留白；(b) 舞台**根本没有渲染素材底图**，
  所以「素材 1」在界面上只是一片灰。
  改动：
    · gp_map_stage：外层 `ColoredBox` 填满整个格子（同底色收边，消除
      「舞台周围一圈空白」），内层 `Center + AspectRatio(16/9)`；
      `GpMapStageKeys.stage` 仍挂在 16:9 节点上（几何断言继续可测）。
    · 新增 `_coverImage`：取最新公开素材的 dataURL → base64Decode →
      `Image.memory(fit: BoxFit.contain)`（不裁切、不变形；解析失败静默降级）。
    · room_game_page `_slotView`：map 类格子不再包竖向
      SingleChildScrollView，直接拿紧约束（否则高度无界、舞台只能按宽度
      算高、格内留白）。
  如实披露：**这一项不是「本来坏了」**——16:9 的 AspectRatio 早已存在，
  真问题是「素材图没渲染 + 格子过高留白 + 外层被滚动容器放开约束」。

■ ⑥ 骰子文案去 1 + 其他骰子收纳 —— gp_dice_bar.dart
  改动：
    · 新增 `_diceLabelOf`：显示 `D100/D4/…`（去掉前导 1）；
      **内部表达式 `kDiceExprs` 仍是 `1D100/1D4/…`，载荷与规则层一字不动**。
    · 工具栏只留 D100 + 自定义；新增「其他骰子」按钮（`GpDiceBarKeys.otherDice`）。
    · 点「其他骰子」→ `showGeneralDialog` 居中 Dialog，里面 D4/D6/D8/D10/D12/D20
      （复用同一个 `_roll` 回调，key 仍是 `GpDiceBarKeys.expr(e)`）。
  口径更新：
    · p10_t6_layout_test B1 keys 列表：`for(final e in kDiceExprs)` →
      `expr(kDiceExprs.first) + otherDice`。
    · room_ui_blocks_test：点 1D6 前先打开「其他骰子」；旁观者 keys 列表
      改为 D100 + otherDice。
  证据：p10_t7 T3 断言「工具栏无 D4~D20、弹窗 6 个都在、点 D6 仍发 1D6」。
