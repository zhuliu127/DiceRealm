【3】★ 切场景必停旧 BGM —— 行为级证据

`MusicConsoleController.switchScene()` 是**同步顺序调用**：
  ```
  _port.stop();                       // ① 无论旧场景是否在播，显式停一次
  _activeSceneId = sceneId;
  if (!slot.configured) { ...; return; }   // 空插槽 = 停旧的、不播新的
  _port.play(slot.relPath);           // ② 旧流已停，才播新的
  ```
生产实现 `SystemMusicPort._play()` 里还有 `await p.stop()` 双保险。

Fake 记录到的真实调用序列（用例 A1）：
  第一次 `switchScene('daily')` → `['load','stop','play:music/daily.mp3']`
  第二次 `switchScene('combat')` → 增量恰好 `['stop','play:music/combat.mp3']`
  断言：`stop` 索引 < `play` 索引、`overlaps == 0`、`activeStreams == 1`。
  空插槽（A2）→ 增量恰好 `['stop']`，`activeStreams == 0`、状态「已停止」。
  KP 快捷弹层（A6）同样记录到 stop 早于 play、零叠播。

★ 反向证伪：把 `_port.stop()` 从 `switchScene` 摘掉 → A1 立刻红
  （`00:02 +0 -1: A1 ★ 切场景：stop 严格早于 play…`），见 §8 表。
