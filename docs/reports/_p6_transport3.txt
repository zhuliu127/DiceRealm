二、UI 接线的架构决策
----------------------------------------------------------------
问题：`_RoomShell` 原来吃 `RoomBoot`，而 `RoomBoot.host` / `RoomBoot.hub`
      是非空字段 —— 远端会话根本没有这两个东西。
      但它们也不能改成可空：`boot.host` / `boot.hub` 在测试里用了 10+ 处。

解法：把 `_RoomShell` 的入参从「一个 RoomBoot」拆成「它真正需要的四样」：
      session（抽象 RoomSession）/ local / controller / onClose
      然后 `_openRoom(boot)` 和 `_openRemote(remote)` 各自装配、走同一个
      `_openShell(...)` 出口。

收益：
  · `RoomBoot` 一个字段都没改，10+ 处测试零改动；
  · UI 层从此**不知道**自己在本机还是网络上 —— 这就是 P6 想证明的事；
  · 退房清理各管各的（本机收存档，远端断连接 + 收 local）。

一个刻意细节：`_openRemote` 里 `RoomUiLocal` 必须**新开一份**。
本机建房那套 local 里有工具模式、折叠态、手绘分页等本地状态，
两个房间共用会串味（A 房的折叠态跑到 B 房）。

三、协议补全：座位自动分配
----------------------------------------------------------------
写接线时发现一个致命缺口：`_onHello` 要求 `seat` 必须在花名册里，
但**局域网加入的玩家根本不知道有哪些座位** —— 他们只知道房号。

不补这条，「加入」功能就是废的。

补法（服务端）：
  · `seat` 为空 → `_freeSeat(role)` 找第一个空闲 `p1..p6`
  · 找到后调 `host.attachPeer(...)` 真的把人加进花名册（P4 唯一合法入口）
  · 满了 → `ROOM_FULL`
  · 指定了 seat 但花名册里没有 → 仍拒 `UNKNOWN_SEAT`（不能凭空造座位）

补法（客户端）：
  · `seat` 改成非 final；`joined` 帧回来后如果分配了不同座位就更新
  · **`RoomClient` 必须重建** —— 裁剪口径是按 seat 算的，
    用旧座位接收会看到别人的数据或什么都看不到

★ 判断「座位有人了」的依据是**花名册**而不是 `_peers`：
  `attachPeer` 一执行座位就进花名册，花名册才是唯一真相。

四、加入流程的产品行为（已写进 UI 文案）
----------------------------------------------------------------
  输 6 位房号 → 先扫 1.2s 局域网找这间房
    ├─ 找到 → 连上去，横幅「已连上局域网房间（实时同步）」
    └─ 没找到 → 回退本机预览，横幅「…找不到则以「本机预览」进入
                （只有你自己看得到）」

测过的文案断言：
  · 常驻说明（joinHint）必须含「本机预览」—— 不骗用户；
  · 回退后的横幅必须含「本机预览」；
  · 原来那句「局域网联机在下一期（P6）」已按事实改写。

★ 顺带一个测试工程问题：UI 测试跑真 UDP 扫描会慢 1.2s/用例，
  且不同机器受防火墙影响结果不稳定（造出假红）。
  加了 `RoomNetFactory.discoveryEnabled` 开关，测试 `setUp` 里置 false。

五、修的一个真缺陷：dispose 不幂等
----------------------------------------------------------------
现象：测试 tearDown 与测试体各调一次 `RemoteSession.dispose()` → 崩
      「A RemoteSession was used after being disposed」。

这不只是测试问题：UI 里 `State.dispose()` 与路由 pop 也常常各调一次。

修法：两处都加 `_disposed` 守卫。
`HostingLocalSession` 还多做一件事：**在同步的 `dispose()` 里也发起
`server.stop()`** —— UI 走的是 `State.dispose()`（同步），不会 await
`shutdown()`，只靠 shutdown 停服务会留下幽灵房。
