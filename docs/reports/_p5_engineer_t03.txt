三、五个子批次的实现要点
----------------------------------------------------------------
S3.1 素材舞台（gp_map_stage.dart）
  · `MapStageControl implements MapStageController` —— §3.9 六个成员签名一字不改，
    另暴露 `mode / strokeColor / strokeWidth / markKind / markLabel / markRevealed /
    actorName / playerSeat` 给舞台自己读（块 3 仍只认接口）。
  · 坐标：`stageNormOf(Offset, Size)` 纯函数（clamp 到 [0,1]，零尺寸不出 NaN），
    `stagePointJson` 产出 `{x,y}` —— 与权威端 `mapStroke` / `mapMark` 同形状。
  · 落点三态：mark → `map.mark{...}`；placeActor / placePlayer → 回调交出
    (名字, 归一化点)，真正的结算留给 T04；落一次即 `cancel()`（单次工具态）。
  · 画笔：手势期间攒归一化点，**手势末尾一次** `map.stroke{color,width,pts}`。
  · 橡皮：手势末尾用 `eraseStrokeSegments(strokes, path)` 算好整份，**一次**
    `map.strokes.set{strokes}`（段级删除，不是整条删）。
  · 只读：`readOnly:true` 时任何手势都不发包（玩家侧与全屏弹层同一条路径）。
S3.2 聊天与游戏记录（gp_feeds.dart）
  · `FeedList` 用 `ListView.builder` 懒构建；`didUpdateWidget` 里「本来就在底部
    才跟随」，用户上滚回看时不抢滚动位置（P0-06）。
  · `FeedRow` 五类分派全走 view/feed_view 的纯函数（`diceLine` / `checkLine`），
    本文件不解析任何载荷 → 结构上不可能渲染出原始键名。
  · `ChatInputRow` 把 `TextEditingController` 放在自己的 State，草稿另存
    `RoomUiLocal.chatDraft`；旁观者 `TextField.enabled == false`。
S3.3 只给你看（gp_privates.dart）
  · `privRowsOf(state, seat, limit:12)` → 正序；新条 = seq 严格大于上一帧最大值，
    首帧不标（否则一进房间全亮）；点条开全文、⛶ 开全屏。
S3.4 战斗列表 + 状态条
  · 战斗：`hpPublic==false` → 「HP 隐藏」；`hpMax==0` → 只显当前值且**不判死**；
    KP 侧 `combatRows(isKp:true)` 用 secret/kpOnly 补全；「下一个行动 ▶」
    **只在 KP 侧渲染**（T-22），玩家侧 findsNothing。
  · 状态条：KP 读 `hostRead.pending`（T7，不在 state 里找）→ `INTENT.CONFIRM`
    `{op, by, agree}`；玩家读自己裁剪态的 `requests` → `INTENT.CONSENT{id, agree}`。
    `state.request` 在 pending 里留的**记账条目**被跳过（它的确认方是玩家）。
S3.5 骰子条（gp_dice_bar.dart）
  · 只发 `INTENT.DICE{direct:true, expr, bonus, penalty, [secret]}`，**不自算结果**
    （载荷里没有 result/total/rolls/value，有专门用例钉死）。
  · 奖惩骰互斥 + 0–5 由 `RoomUiLocal.setBonus/setPenalty` 一处实现，骰子条只透传。
  · 暗骰 → `secret:true`：结论是「公共骰栏为空 + 私有账有内容 + 他人视图无骰值明细」，
    三条都在用例里断言（B1-F1 的回归网）。

四、本轮被测试逼出来的三个真实缺陷（都已修）
----------------------------------------------------------------
① **块内必须自己订阅 `local`**：`RoomScope` 是 `InheritedNotifier<RoomSession>`，
   只订阅会话；骰子条（奖惩骰/暗骰文案）与战斗列表（tab 切换）都读本地态，
   不订阅就「点了数字/内容不刷新」。→ `GpDiceBar` / `GpCombatList` 各自包
   `ListenableBuilder(listenable: scope.local)`。（与 T02 的 `GpToolbar` 同一个坑，
   已在报告里提醒：**凡读 local 的块都必须自己订阅**。）
② **权限按钮应当「不渲染」而不是「禁用」**：T-22 要求玩家侧没有「下一个行动」。
   改成 `isKp ? RoomTap(...) : null`，`combat.roll` / `check.opposed` 同理按
   `gate.can(op)` 决定渲不渲染；`enabled` 仍恒等 `gate.can(op)`，T-30 探针两种分支都成立。
③ **测试侧的 pan 手势门槛**：`tester.dragFrom` 只有起止两点且要越过 18px slop，
   拿它测「段级擦除」会擦不中（容差 2%）。改用 `startGesture + 多次 moveTo`
   造一条**穿过**笔迹的路径 —— 这条已写进用例注释，T04 做橡皮时会用到。
