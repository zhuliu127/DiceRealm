二、环境搭建踩的坑（全部解决）
----------------------------------------------------------------
1. **sdkmanager 必须直连**（不传 `--proxy`）
   之前传 `--proxy=127.0.0.1:9194` 一直 `Connection refused`；
   直连 `dl.google.com` 返回 200。代理参数反而把可用的直连搞坏了。

2. **两个包一起下会 zip 损坏**
   `sdkmanager "emulator" "system-images;..."` 一起下 → 15 分钟后报
   `Error on ZipFile unknown archive`（下载被截断，工具不校验大小就解压）。
   单独装 emulator 成功；system-image 仍损坏 → 改为手动 curl 下载：
     curl -L -C - -o sysimg.zip \
       https://dl.google.com/android/repository/sys-img/google_apis/x86_64-35_r09.zip
   （1.61G，8 分 56 秒，3.09MB/s）
   解压到 `system-images/android-35/google_apis/` 即可被 avdmanager 识别
   （zip 顶层就是 `x86_64/`，不用额外写 package.xml）。

3. **Git Bash 会把 Android 路径当 Windows 路径转换**
   `adb shell uiautomator dump /sdcard/ui.xml` 里的 `/sdcard` 被转成
   `C:/.../PortableGit/sdcard`。解法：加 `MSYS_NO_PATHCONV=1`。

4. **两台模拟器一起跑会崩**
   每个吃 2-3G RAM，第二台起来后系统「Messages」先 ANR，
   随后 emulator-5556 直接 `error: closed`（进程挂了）。
   ⇒ 双模拟器不可行，改为「模拟器当服务端 + 宿主机当客户端」。

四、真机抓到的 bug（单测发现不了）
----------------------------------------------------------------
现象：`/health` 说 `players:1`，但 KP 界面「成员（0）」不更新。

根因：远端玩家加入时，`LanServer._onHello` 调用的是**自己的** `pump()`
（只把计划发给网络连接），**没走 `HostingLocalSession.pumpPlans`**
（那才会 `_hub.notifyAll()` 通知本机 UI 重建）。
同理 `_onFrame` 处理远端 intent 时也一样。

为什么单测发现不了：
  `p6_room_net_factory_test` 里的「KP 发言 → 玩家收到」是 KP 主动发起的，
  走的是 `session.sendIntent` → `pumpPlans` → 本机+网络都发。
  而「远端加入/远端发言」这条反向路径，单测只断言了**网络侧**（玩家收到），
  没断言**KP 侧自己的 UI 会不会刷新**。

修法：
  · `LanServer` 加 `onHostPlans` 下游（未注入时退回直发网络，兼容单测）
  · `HostingLocalSession` 构造时 `server.onHostPlans = pumpPlans`
  · `LanRoomHost` 透传并缓存（构造时服务可能还没启动，start() 后再应用）
  · 所有 `host.intent()` 的产出统一走 `_dispatchHostPlans`

补的测试：
  「远端加入后 KP 侧成员表应立刻更新」—— 断言 `session.state['members']`
  在远端 join 后增加。这条测试是回归护栏，防止再退化。

★ 教训：**双向都要测**。只测「我发出去对方收到」不够，
  还要测「对方发过来我自己有没有反应」——后者才是 UI 刷新的路径。

五、顺带修的两处「骗用户」文案
----------------------------------------------------------------
1. 房间页「服务地址」区块原来写着
   「本机进程内房间：P5 没有网络服务，局域网联机在下一期（P6）」
   —— 明明已经开了局域网却在说没有。
   改成：有地址 → 显示真实地址（可选中）+「同 WiFi 的同伴可在「加入」里手输这个地址」；
        没地址 → 「未开局域网服务（端口被占或没连 WiFi）：这间房只有你自己能进」。
   「复制地址」也从假的 `local://room/$code` 改成真实 base。

2. 加入区的常驻说明、建房按钮 hint 一并按 P6 的事实改写。

配套给 `RoomSession` 加了 `lanBase` 能力位（KP 侧返回真实地址，
玩家/旁观恒 null），UI 据此决定显示什么 —— 不靠猜。

六、仍未验证的部分

  这一环只能用真机验。当前已有「手输地址」兜底，即使发现失效也能加入。

  加 `CHANGE_WIFI_MULTICAST_STATE` 并在运行时申请 MulticastLock。
  这条留给真机首测时确认。
