二、局域网自检（net/lan_diagnose.dart + sheets/sheet_lan_check.dart）
---------------------------------------------------------------
设计出发点（旧版 room-net.js:418 `lanDiagnose` 的原话精神）：
  **不是「报个错」，而是把「连不上」拆成几个可行动的原因。**

5 种 verdict，每种对应一句「你该做什么」：

| verdict      | 含义                     | 处置                                  |
|--------------|--------------------------|---------------------------------------|
| lanOk        | 局域网地址可达           | 把地址发给同伴                        |
| lanDown      | 本机没起服务             | 先去建房                              |
| lanBlocked   | 回环通、局域网地址不通   | 查 AP 隔离 / 访客网络 / 防火墙 / 网卡 |
| lanTimeout   | 两探都超时               | 关防火墙、换 WiFi                     |
| lanDead      | 两探都失败               | 服务崩了或端口被占，重建房            |

四个探测步骤（串行，不是并发）：
  ① 局域网服务是否启动（lanBase 非空）
  ② 网卡清单 + 哪块被选中
  ③ 打 base/health（同伴真正要用的地址）
  ④ 打 127.0.0.1:port/health（回环对照）

★ 为什么串行：先打局域网地址，再打回环做对照。
  「局域网不通但回环通」这个组合本身就是结论 —— 服务活着，是这个 IP 走不通。
  并发的话两个结果同时回来，反而看不出因果。

★ 判读顺序有讲究（本批最重要的一条设计）：
   loopOk 必须先于 anyTimeout 判断。
   「服务活着」比「某一探超时」是更确凿的信息。顺序反了会把
   「AP 隔离」误报成「防火墙丢包」，处置方向就错了。
   抽成纯函数 `judge(lanOk, loopOk, anyTimeout)` —— 三个布尔值就能决定，
   留在 I/O 流程里就只能靠真网络去测，而「拒绝 vs 超时」在各系统上结果不同。

★ 比旧版多一件事：列出所有网卡并打分。
   浏览器里拿不到网卡列表，Dart 可以。这直接解决「选错网卡」这个
   最难自查的问题 —— 我本人就被 Clash 的 TUN 网卡（198.18.0.1）坑过：
   服务"启动成功"、界面显示"已连接"，但广播出去的地址同伴根本连不上。
   弹层会把 `198.18.x` 标红并写明「VPN 虚拟网卡」。

四、本批修的真 bug：Dart 不认 JS 的 `$1` 捕获组
---------------------------------------------------------------
`_swapHost(base, host)` 原写法：

    base.replaceFirst(RegExp(r'^([a-zA-Z]+://)[^:/]+'), '\$1$host');

Dart 的 `replaceFirst` **不支持** `$1` 捕获组语法（那是 JavaScript 的），
会把 `$1` 当字面文本拼进去 → 拼出 `http://$1127.0.0.1:4211` 这种废 URL。

后果不是小瑕疵：**回环探测永远失败**，于是「局域网不通但回环通」这条
最有价值的判读（lanBlocked）**永远走不到**，所有连不上的情况都被误报成
「服务崩了」。

修法：

    base.replaceFirstMapped(
      RegExp(r'^([a-zA-Z]+://)[^:/]+'),
      (Match m) => '${m.group(1)}$host',
    );

这条是靠测试红出来的：预期 lanBlocked，实际 lanTimeout。
连带发现「用真 socket 造拒绝 vs 超时」在各系统上不稳定，
于是把判读抽成纯函数单测 —— 顺手让设计更清晰。
