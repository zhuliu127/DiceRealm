# 设备适配报告（Magic9 手机 / 荣耀平板 GT2 Pro）

## 实测设备与逻辑尺寸

| 设备 | 物理分辨率 | 屏宽推断 dpr | 逻辑尺寸 | 命中断点 |
| - | - | - | - | - |
| 荣耀 Magic9 标准版 | 2664×1236 | ≈3.0 | **≈412×888**（竖屏） | compact（<600） |
| 荣耀平板 GT2 Pro | 3048×2032 | ≈2.0 | **≈1524×1016**（横）/ 1016×1524（竖） | expanded（≥840） |

> dpr 是按 6.8" / 12.5" 屏的常见取值估的；真机 `MediaQuery` 若不同，逻辑宽仍分别落在
> compact 与 expanded 两档，所以适配策略不变。

## 做了什么

### 1. 新增响应式基础 `lib/ui/responsive.dart`
- `Bp`：沿用 Material 3 三档断点 `compact 600 / medium 840 / expanded`
- `ContentFrame`：阅读型内容限宽 **760dp** 居中；**窗口 ≤760 时完全透明**（手机不受任何影响）
- `BannerSlot`：按宽度等比的装饰图钳高度上限
- `byWidth / columnsFor`：三档取值与列数助手

### 2. 装饰条限高（平板核心问题之一）
`SectionBanner` 原用 `AspectRatio(6)`：412dp 上是 69px（正好），**1524dp 上是 254px** —— 一条装饰吃掉四分之一屏。
改用 `BannerSlot(maxHeight: 96)`，超出部分由 `BoxFit.cover` 从两端裁掉（装饰条两端本来就是留白）。

### 3. 阅读型页面限宽
| 页面 | 限宽 |
| - | - |
| 首页 | 760 |
| 角色档案（名册） | 760 |
| 车卡九步向导 | 820 |
| 设置页 | 待接（见遗留） |

理由：1524dp 上不限宽，一行中文要横扫半个屏幕，眼睛回行必丢行。

### 4. 手机（412dp）
- 现有单列布局本就适配，**未引入任何额外留白**（ContentFrame 在 ≤760 时是直通的）。
- 首页四宫格、名册一行一张、向导单列，在 412dp 上均无需改动。

## 待接 / 遗留

| 项 | 说明 |
| - | - |
| 设置页限宽 | 结构简单但 `ListView` 嵌套层数多，改动风险大于收益，暂缓 |
| 名册平板双列 | 长条卡高度不定，`GridView` 需要固定 `mainAxisExtent`，需逐个量高度；限宽后已可读，优先级低 |
| 向导平板双列（左表单右预览） | 收益最大但属于布局重构，应单独立项 |
| 游戏页 | 已有 `RoomGridSpec` 按 w/h 自适应分栏，无需额外处理 |

## 验证
- `flutter analyze` 零问题
- 全量 `flutter test` **1636 组全绿**（限宽未破坏任何既有断言：分类头左右边界、四宫格首屏可见、同行对齐等均仍成立）
