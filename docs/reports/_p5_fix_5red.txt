【红 1 & 红 2】test/qa_p5_priv_probe_test.dart → A-4 state.self / state.edit.self
  现象：① 旁观者点了能发出 state.self；② 点「轻伤」后 UI 宣称「已更新」

  根因（两处，都在实现侧，是真缺陷）：
  A. lib/ui/room/widgets/gp_pl_char_card.dart:195
     `GpPlCharCardKeys.stateBtn` 在 `if (!locked)` 分支里**无条件渲染**。
     旁观者（sp1）没有「我的角色」语义，却看到了「状态管理」入口。
     违反 T03 已确立的口径：**权限不足应「不渲染」而非「禁用」**。

  B. lib/ui/room/sheets/sheet_self_state.dart:_applyBody / _applyMental
     两个方法**完全没有权限门控**，直接：
         scope.controller.hostAction('state.self', {...});
         scope.local.showNotice('身体状态已更新（立即生效）');
     权威端按 POLICY 拒绝（state.self 只放 player/kp，spectator 不在内），
     但 UI 已经无条件宣布成功 —— 直接违反 K7「不乐观提示成功」。
     这比测试描述的更严重：**任何能打开弹层的路径都能造成假成功提示**。

  修法（双保险，与 T-20/T-30 同一模式）：
    第一层 · 入口不渲染：
      gp_pl_char_card.dart  stateBtn 外包 `if (scope.controller.gate.can('state.self'))`
    第二层 · 内层门控：
      _applyBody / _applyMental / _submitNumbers 开头加
        `if (!scope.controller.gate.can(<op>)) { showNotice('你没有权限…'); return; }`
      不乐观提示：无权时只说事实，不改任何「已更新」文案。

  测试改动（把「现状记录」翻转为修复后的正确期望）：
    · 「旁观者点「轻伤」后…」重写为两条：
      1. 旁观：入口结构性不渲染（stateBtn findsNothing）+ 点遍页面零发包 + 权威态不变
      2. 双保险：绕过入口强行 openSelfStateSheet 打开弹层，点「轻伤」
         → 仍零发包 + 权威态不变 + notice 不含「已更新」
    · 保留正向守卫：玩家侧 stateBtn findsOneWidget、点「轻伤」真的发 1 条 state.self

【红 3 & 红 4】test/room_ui_permission_test.dart → T-30 锚点表
  现象：Expected <31> / Actual <30>；③ 无锚点清单 at [8] is 'combat.enqueue' instead of 'combat.prepare'

  根因（实现演进，不是缺陷）：
    `combat.enqueue`（加入战斗的候选行）的入口从 `RoomKeys.action('combat.enqueue')`
    改成了专用 key `GpCombatKeys.enqueueRow(seat)`。
    原因成立：候选列表**每行一个座位**，必须区分（p1/p2/p3…），
    单值 `act/<op>` 锚点表达不了多行 —— 一个 op 只能挂一个 key。
    于是它从「有锚点」迁到「无锚点」，两侧清单各让一位：
      锚点表 31 → 30；无锚点清单 30 → 31；两者相加仍 = POLICY 61 条。
    门控没有丢失：`_CombatEnqueueBody` 里 `enabled: can`（= gate.can('combat.enqueue')）。

  修法：
    · `expect(table.length, 31)` → 30，并写明迁移理由（不写理由就是裸改数字）
    · `kFrozenNoAnchor` 按字典序插入 'combat.enqueue'（在 combat.prepare 前）
    · 保留 `noAnchor.length + table.length == 61` 这条铺满校验 —— 它证明没有漏测

  为什么这不是「改测试让它绿」：
    如果 combat.enqueue 的闸门真的丢了，T-30 的原断言会失效，但
    `qa_p5_priv_probe_test.dart` 的专用 key 探针 + `enabled == gate.can`
    的等价检查仍会抓到。锚点迁移只是换了覆盖手段，覆盖面没缩小。
