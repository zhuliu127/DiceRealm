================================================================================

2.1 根因
  `lib/domain/room_model_actions_combat.dart:52` 的 `combat.roll` 与
  `dice.roll` 共用一个分支 → `diceRoll(seat, p)`；而 `diceRoll`(:746) 直接吃
  客户端 `p['result']`（`value` / `levelText` / `rolls` / `levelKey`），
  权威端不做复算。`POLICY`(`room_types.dart:286`) 是 `['kp','player']`，
  于是玩家一次 `intent` 就能把 `total:1 / 大成功` 写进权威 dice 记录并
  `to:'*'` 广播。旧版 `applyAction`(:1702-1862) 对 `combat.roll` 无分支，
  是别名补齐带来的新面，不在 fixture 等价比较范围内。

2.2 改法（唯一源码改动：lib/domain/room_model_actions_combat.dart:50-74）
  拆开 `dice.roll` 与 `combat.roll` 两个 case：
    case 'dice.roll':  return diceRoll(seat, p);            // 原样
    case 'combat.roll':
      if (seat != kHostSeat) {
        return diceDirect(seat, roster.get(seat), RoomRole.player,
            <String, Object?>{
              'expr': p['expr'], 'label': p['label'], 'skill': p['skill'],
            });
      }
      return diceRoll(seat, p);                             // KP 原样
  · 复用既有 `diceDirect` 的权威掷骰能力：`expr != '1D100'` 走
    `rules.rollExpr(expr, rng)`，`'1D100'` 走 `rules.check(opts)`
    （`skillBaseOf` 从权威花名册/角色卡取 base），结果由权威端 rng 算出。
  · **只透传 expr / label / skill**：客户端的 `result` 被彻底丢弃；
    `secret`（会把广播改成 SEAT 定向）、`reqId`（会附带 settleRequest）、
    `base/bonus/penalty/difficulty`（会影响检定难度）、`damage/hp/slotId/target`
    等夹带字段一并不透传。
  · KP（`seat == kHostSeat`）保持 `diceRoll(seat, p)` 原样，权威端可自报。
  · `POLICY` 仍 `['kp','player']` 一字未动；`state.dice` 记录结构（reduce
    的 10 个键）与 `to:'*'` 广播对象不变；`reduceRoomState(` 调用点未增。
  · randUsed：非 host 的 1D100 走 check 会多消耗 2 个随机数、非 1D100 走
    rollExpr 按骰数消耗，符合派工「会多消耗随机数」的预期；`combat.roll`
    结算不在 fixture 等价比较范围内（旧版无分支），1349 例不受影响。

7. 相对设计 / 派工的偏差与说明（全部列明，无隐瞒）
================================================================================
  (1) `allowedPaths` 用运行期完整路径 `hostScript / F:4#900001.snapshotSeqs[0]`
      而非文档语法 `r'$.snapshotSeqs[0]'`。原因见 1.3：`RoomOracleFixture.run`
      把用例标签当比较根路径。若登记 `$.` 形式，运行期不命中、测试会红；
      若改 `room_oracle.dart` 根路径，则会让 S:q1 的 14 条 `$.` 路径从
      「死登记」变成生效 = 放宽比较器，违反硬约束。故选精确的运行期路径，
      仍满足「精确、禁通配、只放行这一场景差异的路径」。
  (2) `S:trim` 在 `room_sequences.json` 零命中（只靠 `exactCaseNames` 精确
      点名 `qa_p4_fresh_oracle.json` 的 F:4#900001）。派工提到的
      `whitelistedTags == {'S:q1','S:trim'}` 已按「登记在册的 caseId 集合」
      落实在 `room_coverage_test.dart`；fixture 里实际命中集合仍是
      `{'S:q1'}`（因为不能改 fixture 加 S:trim tag）。
  (3) F4 非 host 只透传 expr/label/skill，不透传 base/bonus/penalty/difficulty。
      这是为避免玩家借 `combat.roll` 影响权威检定难度（比派工要求更严），
      不改变 dice 记录结构、广播对象与 POLICY。
  (4) QA 域的 3 个测试文件（`qa_p4_seq_rollback_edges_test.dart` /
      `qa_p4_whitelist_strength_test.dart` / `qa_p4_alias_actions_test.dart`）
      有改动，原因是它们断言的正是「修复前缺陷现状」或「白名单恰好 1 条」，
      裁决变更后必须同步；未删除任何用例，且额外补了 2 例强度断言。
  (5) `tool/qa/qa_p4_gate.js` 未改（按派工要求），故其 IS_PASS 为 NO；
