旧版 `exportArchiveText(a)` 的确切格式（逐字对齐）：
  跑团游戏历史记录
  ================================
  房间：{name || '房间 '+code}（房间号 {code}）
  KP：{kpName || '—'}
  结束时间：{endedAt ? archiveLogTime(endedAt) : '—'}
  成员：{members.map(nickname + （charName）).join('、') || '无'}

  最后 `UI.saveFile('游戏历史记录-<safeName>-<code>.txt', text, 'text')`，
  成功才 toast「已导出 N 条记录」。**只有 logs 一节，不含 chats**。

★ 关键决策（逐条写清「为什么」）
 1. **导出对象改了**：旧版导出的是「结团归档」实体 `a`（有 endedAt / members /
    logs / dice）；本工程当前没有归档实体，只有 `session.state` 与存档槽。
    因此导出的是「**当前会话视角的公开信息流**」，抬头「结束时间」改成
    「导出时间」（由调用方注入时钟，纯函数不读系统时间），并新增
    「导出视角」与「说明」两行如实交代边界。这是能力差异，不假装是归档文件。
 2. **包含列（只公开）**：房间名 / 房号 / KP / 导出时间 / 成员（昵称 + 角色名）/
    导出视角 / 说明 / 游戏记录（编号、时间、执行者、公开 text）/ 聊天记录（同款）。
    公开骰走 `diceLine` 的 UI 文案（'1D100 → 42 · 困难成功'），不按 rolls 重算。
 3. **是否过滤秘密字段：过滤，且是结构性过滤**。纯函数**只**调用
    `view/room_view.dart` 的 `codeOf / roomNameOf / kpNameOf / membersOf /
    roleText` 与 `view/feed_view.dart` 的 `collectFeeds / collectChats /
    checkLine`，也就是项目既有的「当前玩家可见公开字段」唯一裁剪口径。
    它绝不遍历 `state['privates']`、`state['logs']` 原始行、`state['dice']`
    原始表，绝不调 `LogRecord.toWireJson()`（那份带明文 `p`），不读角色卡
    `sheet`、不读 `wire` / `p` / `opp` / `rolls` / `label` 原始结构，
    不读私有素材、暗骰结果、私密笔记、其它座位私有字段。
    测试用 10 个哨兵串逐一断言零泄漏，同时用正例断言「公开内容确实在」，
    防止靠「什么都不输出」骗过断言。
 4. **redacted（暗骰）行**：照 `feed_view.dart` 口径只取 `text`，`opp` /
    `seat` / 结构化结果一律不进导出。**执行者统一写「系统」**，不写旧版的
    「KP（暗骰）」—— 连「这里发生过暗骰」这一元信息都不写进导出文本。
    这是与旧版唯一有意的行为差异，理由就是 K3 收紧。
 5. **顺序与旧版一致**：两节都按 `at` 升序（同 at 按 seq，复用 `collectFeeds`
    的排序），编号从 1，行格式 `[YYYY-MM-DD HH:MM:SS] 执行者：内容`。
    没有第二套排序或第二套解析。
 6. **分节**：旧版只有「游戏记录」一节（logs）；本工程把公开聊天单列
    「聊天记录」一节，因为 `collectChats` 是既有公开只读口径、界面上本来
    就有聊天栏。两节各自「共 N 条」+ 分隔线 + 独立空态文案。
 7. **上限与截断**：`feedLimit=120` / `chatLimit=60` 与 U11「记录 120、
    聊天 60（只裁显示）」同源，取最近 N 条；单行按 Unicode 码点截断到 160
    （不拆坏 emoji），换行 / 制表符摊平成空格（否则会伪造出额外记录行），
    超出追加「…（已截断）」；`maxLineChars <= 0` 显式表示不截断。
 8. **null 不印 null**：所有取值走既有 `roomText`（null → 空串），
    **零新增 `jsStr(`、零白名单**。门禁复核 `jsStr(` 总数仍是 14、白名单
    外 0 个文件。
 9. **视角**：入参 `state` 已是「按座位裁剪过的会话态」，过滤发生在数据层；
    `seat` / `role` 只用于抬头如实写清导出视角，**不做二次隐藏**（T8：
    二次隐藏会让跨视角用例假绿，等于第二套权限实现）。测试专门断言
    「同一 state 换视角，去掉抬头行后正文逐字一致」。
10. **K7 不造假入口**：旧版靠 `UI.saveFile` 下载 .txt；本工程在自动化环境里
    平台通道不返回，所以底线是「**完整文本 SelectableText 上屏 + 可全选
    复制**」，再叠加「复制」「系统分享」两个真动作。没有「已导出成功」假提示、
    没有文件名、没有本地文件写入；用户可以复制 / 分享文本后自行保存。
    平台动作抽象成 `RoomHistoryExportPort`（同步返回 void）：测试注入同步
    计数替身 / 空 port；生产用 `SystemRoomHistoryExportPort`
    （`Clipboard.setData` + `SharePlus.instance.share`）。
    widget 里**零 await**：先 `setState` 同步上屏反馈，再触发平台动作；
    反馈不依赖副作用完成。零 Timer / 零 Future.delayed / 零 AnimationController。
    `share_plus ^13.3.1` 是现有依赖，`pubspec.yaml` 未改。
11. **权限沿用 `gate.can(op)`**：导出是「公开信息流的本机只读副本」，不是新
    的权威动作，所以**不新增 POLICY op、不加白名单、不另写一套权限判断**，
    直接复用 `kRoomHistoryExportPolicyOp = 'chat'`（POLICY = [kp, player]）。
    该常量只在 `sheet_history_export.dart` 定义一次，三处使用：
    `MiscSheet` 入口（结构上不渲染）、`RoomGamePage` 玩家「更多工具」路径、
    弹层 `canExport` 二次防御。旁观者 `gate.can('chat') == false` → 不渲染入口，
    且零发包。
    ★ **待 QA 判的拿不准处**：`room_model_host_core.dart#syncFor(seat)` 对
      spectator 也下发公开 `chats / logs / dice`，理论上旁观者看得到公开
      历史。按派工「权限不足不渲染入口」取了保守口径（排除旁观者）。
      是否应向旁观者开放只读导出，请 QA 判定；若放行，只需改这一处常量映射。
12. **生产可达路径**：`MiscSheet` 此前**只能从 KP 工具面板**打开，玩家没有
    可达路径。P2-06 的真入口装在 MiscSheet 里，于是给
    `RoomGamePage._buildToolbar` 的非 KP、且 `gate.can(chat)` 为真的视角
    补一个「更多工具」入口（`RoomGamePage.miscToolsKey`）。KP 不重复摆
    （它走 KP 面板）；旁观者不渲染。**导出入口本身只有 MiscSheet 一处**。
13. **零发包 / 零网络 / 零 state**：弹层不调 `hostAction` / `sendIntent`，
    不写任何 `state[...]`，不碰 `local.notice`（反馈在弹层内 setState）。
    接线测试用四项真值前后对比钉死：`f.sent.length`、`session.lastSeq`、
    `jsonEncode(stateOf)`、`local.notice`。

【D2 · 上架签名】
  现状：`android/app/build.gradle.kts:32-36` release 分支仍是
    `signingConfig = signingConfigs.getByName("debug")`，脚本出包尾部也
    如实打印「签名：debug（可侧载安装、不可上架）」。
  改成 release 签名需要：
    · 用户提供 release keystore（私钥）与口令 / alias；
    · `key.properties`（路径 / 口令 / 别名），且**必须**留在工程外或
      被 .gitignore 排除；
    · `android/app/build.gradle.kts` 里新增 `signingConfigs { create("release"){...} }`
      读取 `key.properties`，并把 `buildTypes.release.signingConfig` 指过去。
  为什么本批不能做：私钥必须由用户生成 / 提供并自行保管，写进工程或
    由智能体生成 keystore 都是泄密面；而且真机测试尚未做，签完再改包
    会换指纹、让已侧载的装机失效，**真机测完再签更合理**。
  要不要做：**本批不做**。代价：低（改一个 gradle 文件 + 一份外部配置），
    但依赖是**人**（私钥 + 上架主体），不是代码。
  建议：真机 P0 清单跑完、确认要上架时，由用户提供 keystore 后单独一批做；
    本批**没有**生成任何 keystore、没有写任何密钥、没有改 gradle。
