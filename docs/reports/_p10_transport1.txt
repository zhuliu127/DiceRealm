### A1 一键出卡页「角色信息栏背景」→ 纯色羊皮纸，去掉左右竖线

**根因取证（不是删掉某条 Divider）**

那两道竖线**不是 App 画的**，而是候选卡底纹图**自己**的样子：

- 旧实现 `summary_card.dart#_CardFaceBackdrop` 用 `b_card/b1_card_face_3x4.webp`（3:4 竖图）当卡底，
  那张图上画了一圈**双线金框**；

  于是「左右各有两道竖线」。P11 那套顶部 `ShaderMask` 淡出只能盖住**横**线，管不了竖线。

**修法**

- 新增 `lib/ui/parchment.dart`：`ParchmentSurface`（**零资源文件**）＝
  ① 纯色底（`Palette.surface` 混一点金色暖调）② 左上→右下极轻受光渐变
  ③ 固定种子的纸纤维噪点（自写 LCG，跨 SDK 版本可复现）④ 四角暗角。
- `summary_card.dart` 的 `_CardFaceBackdrop` 换成 `ParchmentSurface`：
  与图片比例**彻底无关**，宽卡窄卡都不会再出现一条直线；不新增任何图片资源。
- 保留 `kCardFaceFade` + `ShaderMask` 结构（P11 用例仍按名依赖它），
  作用变成「顶部柔化 + 底纹不许在头部行画线的结构约束」。

**验收**（`test/p10_t1_ui_paper_banner_test.dart`）

### A2 首页两个标题栏「上下边框被裁」

**根因取证**

`widgets.dart#SectionBanner` 原来用 `BannerSlot(aspectRatio: 6, maxHeight: 96)`：

| 场景 | 宽度 | 6:1 应有高度 | 实际高度 | 框比例 | `cover` 结果 |
| --- | --- | --- | --- | --- | --- |
| 手机竖屏 | 380 | 63.3px | 63.3px | 6.0:1 | 不裁（所以竖屏看不出来） |

**修法**（一处改，A2/A3 全修 —— 本来就是一个组件）

- 高度改为「按比例算，只有真的超过上限才钳」；**一旦被钳就改用 `BoxFit.contain`**，

**验收**：412×888 与 1524×1016 两档都断言「框宽/框高 = 6 ± 0.02」+ `fit == cover`；
另加纯函数用例覆盖「触顶 → contain」的兜底分支（**竖屏一并覆盖**，按用户要求一起查了）。

### B3 结团 / 解散房间「点了没反应，也不退出房间」

**根因取证（两层，缺一不可）**

① **动作根本没执行**（这才是「点了没反应」的主因）：
   `room.close` / `room.end` 在 POLICY 里是 `RoomConfirm.twice`。权威端 `act()` 对需要确认的动作
   是「先入 `pending` 队列，等一条 `INTENT.CONFIRM` 才真的执行」（`confirmPending`）。
   而 UI 这边只有「同一个按钮点两次」这层本地确认，第二次点下去只是**又发了一遍同一个 action**，
   权威端按「同一 pending 去重」把它吞掉 → 只回一句「该操作已在等待确认」，房间状态一点没变。
   *取证*：`bootHostedRoom(...)` 之后直接 `hostAction('room.end')`，
   `meta.status` 仍为 `RECRUITING`、`ended` 仍为 null（改前实测）。
② **即使状态变了也没人把页面带走**：domain 的 `closeRoom()` / `endSession()` 都实现了，
   reduce 也确实写了 `meta.status = CLOSED` / `ended = true`，但 UI 只是在原地重画一遍。

**修法**

- `RoomController.dangerAction(action)`：发动作 + 若 `confirmOf == twice` 就补一条
  `INTENT.CONFIRM {op, by: 本座位, agree: true}`。语义仍是「点两次才执行」（第一次只 arm），不放水。
  三个调用点（大厅「结束房间/结团」×2、KP 面板「结束房间」）全部改走它。
- 新增 `lib/ui/room/room_exit.dart`（纯函数，零 Flutter）：`roomExitOf(state, seat, role, kickedByHost)`
  → `none / closed / ended / kicked` + 一句人话。判定顺序：`ended` > `CLOSED`（我收到过 KICK → kicked，否则 closed）。
- 房间**唯一壳体** `_RoomShell`（`room_entry_page.dart`）监听会话变化：
  ① 回合推进顺带自动保存（C2）；② 判定该离开时 `popUntil` 收掉上面的弹层再 `pop(原因)`，
  回到入口页用**中性色横幅**显示原因（不弹模态，K7）。
- LP 退出即释放：`RoomBoot.dispose()` → `HostingLocalSession.dispose()` → `server.stop()`
  （停广播 + 关 socket + 释放端口），已幂等。

**验收**（端到端，真页面）：入口页创建房间 → 大厅 → 点「结团」一次只进确认态 →
第二次 → **`RoomLobbyPage` 消失、回到 `RoomEntryPage`、横幅含「结团」**；「结束房间」同样。
远端那一半在 B5 的云端用例里覆盖（KP 关房 → 玩家侧 state 变 `CLOSED`）。

### B4 踢人后玩家不离开；离开后无法重新加入

**根因取证（共 4 条，全是查出来的，不是猜的）**

1. **服务端会把「被踢的座位」再分配出去**：`RoomRoster.remove()` 会把座位写进 `kicked`，
   `attachPeer` 对 `kicked` 里的座位回 `rejected + blocked`；但 `LanServer._onHello`
   只调一次 `attachPeer` 且**不看返回值**，照旧回 `joined` →
   客户端以为自己进房了，花名册里却没有他（「进不去也退不出」）。
2. **被踢者收不到那条 members 广播**：`plan()` 的收件人按花名册算，KICK 之后花名册少了他，
   于是「成员表更新」永远不发给他 → 他手里的名单还是旧的（仍含自己）。
   所以「我不在名单里」这条判据**根本不成立**（我第一版就是这么写的，用例当场变红）。
3. **主动退房只摘 socket 不标离线**：`bye` 帧只 `_peers.remove`，花名册那条一直 `online: true`
   → 座位不会被回收（再进来只能拿新座，6 人房堆满幽灵成员后就「假满」）。
4. **客户端离开时不关连接**：`RemoteSession.dispose()` 只摘回调（怕连接共享），
   于是退房后 socket 还挂在服务端，再点「加入」开第二条连接会被「同座重复连接」顶掉。

**修法**

- `LanServer._seatCandidates(role)`：**先回收 `online == false` 的旧座**（回来就坐回原位），
  再给全新座位，且**跳过 `kicked` 里的座位**；`_onHello` 逐个候选试 `attachPeer`，
  被拒就换下一个，全被拒才如实回 `ROOM_FULL`（不再发假 `joined`）。
- `bye` 帧补 `host.detachPeer(seat)`（只标离线、不删成员，他还要能重连回原座）。
- `RoomSession.kickedByHost`（本机 / 远端 / 云三处都实现）：**唯一**「我被踢了」硬信号，
  由会话在收到 `evt/kick` 且只发给自己时置位；`roomExitOf` 用它判 `kicked`。
- `RemoteSession.closeConnection()` + 入口页 `onClose` 里真的关连接。
- 被踢玩家：壳体判出 `kicked` → 立刻离开房间回入口页（横幅「你已被房主移出房间」）。

**验收**：踢人后花名册清干净、`roster.kicked` 含该座、原座重占被拒（「踢得掉」的前提）、
**换座可以回来**；主动离开只标离线、不进黑名单、**同座能重新加入**；
被踢者收到 `kickedByHost` 并判成 `kicked`。

### B5 公网开房加回

**协议只读核实（先读后写）**

本地有服务端源码副本 `coc7th-card-app/tools/room_server.py`（1967 行，线上 `/opt/coc-room/room_server.py` 同源）。
关键事实（服务端头部注释原文）：

- 两条路线**协议完全相同**，只有「谁是权威端」不同；公网时**权威端仍是 KP 手机**，服务端只做「鉴权 + 转发 + 房间目录」，**不持有游戏状态**；
- 控制层：`hub.*`（KP→中继）/ `peer.*`（中继→KP）；`ready` 给成员；
  **「其余：中继只是原样透传的字节，不解析」**；
- 接口：`POST /api/rooms` → `{code, hostToken, wsBase}`；`POST /api/rooms/<code>/join` → `{mtoken, wsUrl}`；
  `WS /ws?code=&t=&d=`（`t`=token，`d`=设备标识，用于「同一人重连回原座」）。

⇒ 应用层载荷是不透明字符串，本 App 放的就是 `RoomFrame` 的 JSON，**与局域网帧同一套编码**，
   服务端**不需要任何改动**。所以这不是「造一个连不上的入口」。

**实现**（`lib/net/cloud_room.dart` + `lib/ui/room/room_session_cloud.dart`）

- `CloudRoomHostLink`（KP 侧）：登记 → 连 WS → `SendPlan` 转成 `hub.broadcast`/`hub.send`（按 cid 路由）；
  入站 `peer.open/peer.close/peer.msg` 反过来调 `attachPeer` / `detachPeer` / `host.intent`。
- `CloudRoomClient`（玩家侧）：`join` + WS + `ready` 拿座位 + 应用层帧收发。
- `CloudHostingSession`（继承 `LocalLoopbackSession`，多投一路网络，与 `HostingLocalSession` 同构）；
  `CloudRemoteSession`（与 `RemoteSession` 同形）。**两个会话对 UI 完全同形**，页面不用知道自己跑哪条路。
- `room_boot.bootCloudRoom()`：登记（拿中继分配的房号）→ 建权威端 → 连实时通道 → 返回同形 `RoomBoot`。
- 入口页：创建区改成**两条路**「开局域网房间 / 开公网房间」；
  公网地址未配置时**不渲染**开房按钮，只给「去设置公网地址」的真入口 + 一句说明；
  已配置时展示中继地址（「云端只转发，不保存任何游戏数据」）。
  加入区：手填地址若是 `http(s)://` → 走公网 join（`RoomNetFactory.joinCloud`）。
- 红线遵守：中继出站只用 `SendPlan.toJson()`（用例断言载荷是 `{k: sync|evt|skip, seq}`，
  **不是** `LogRecord.toWireJson()` 的 `{seq, evt}` 形状）。

**测试怎么做的（不碰真网络）**：`cloudHttp` / `cloudSocketFactory` 两个注入点换成内存替身，
在测试里实现一个「只转发不解析」的小中继，于是
「登记 → 握手 → 权威端计划到玩家 → 玩家 intent 回到权威端 → 关房 → 玩家看到 CLOSED」整条链路都能逐帧断言。

**如实说明（重要）**

- 本轮**没有**对 `https://relay.example.com/room` 做真实端到端联调（本机执行环境不适合跑双端 + 外网）。
  控制层由内存中继逐帧覆盖，但**首次真机公网联调仍需一次现场验证**；失败时界面会如实报错（不假装成功）。
- 设备标识 `d` 目前是「进程内随机、进程内不变」：同一进程内重连能回原座，**重启 App 会算新设备**
  （旧版 Web 用的是 `sha256(packageName:ANDROID_ID)`，Flutter 侧没有不引依赖的等价通道）。
- 公网房间**不做**「起不来就降级成局域网」——用户点的是公网，连不上必须报错，
  否则会拿到一个别人连不上的房号干等。

### C2 推进到下一回合自动保存一次

- 真实 op 核实：KP 面板「下一回合」= `round.next` → `RoomEvt.round` → 写 `meta.round`。
- `RoomCardSaver.onStateChanged()`：游戏期 + 我是玩家 + 绑了卡 + `meta.round` 变了 → 自动写一次；
  **先占回合号再写**，所以同一回合内的任何多次状态变化都不会重复写盘（不乱循环）；
  失败静默（只记 `lastError`，不弹错、不阻塞 UI）。
- 接线在壳体（`_RoomShell`）的会话监听里，与 B3 的离开判定同一处。

**边界（如实）**：远端玩家的自动保存只可能发生在他**自己的设备**上 ——
KP 机器上没有他的卡文件，也没有权限替别人写盘。KP 推进回合时，本机只会保存「自己绑定的那张卡」
（KP 通常没绑卡 → 直接跳过，用例覆盖）。

## 6. 本轮踩的坑（留给下一批）

1. **`jsStr(` 预算**：门禁只给 6 个白名单文件共 14 处。新建的 `room_exit.dart` / `room_session_cloud.dart`
   一开始用了 6 处，直接把门禁顶红 → 全部换成 `roomText()`（`room_text.dart` 是白名单里的唯一入口）。
2. **`find.byType(SectionBanner)` 量到的是 Padding 外框**：含 `top:4/bottom:10`，比例会凭空变小
   （实测 5.38 而不是 6），必须量里面的 `ArtImage` 才算「框」。
3. **被踢者拿不到 members 广播**（B4 根因 2）：第一版判据「我不在名单里」在真实链路下永不成立，
   用例当场变红才发现。教训：判据要能用「收件人视角」复算。
4. **给 `sheet` 无条件加键会砸掉 256 例逐字段等价**（B1）：必须 presence-gated。
5. **大厅按钮在视口外时 `tester.tap` 不会报错**（只是点了没反应）：端到端用例要先把视口调高 / `ensureVisible`。
6. 一次 `cd` 打错目录（2026-08-18 vs 2026-10-08）导致 python 补丁落在错误的工作目录
   —— **已核实另一工作区零文件被改**（`find -newermt` 空结果），随后所有补丁改用绝对路径。

## 7. 关键决策

1. **A1 换底料而不是删图**：只在 `BoxFit` / 裁切上打补丁治不了「4:3 竖图自带的双线金框」，
   换成一幅与比例无关的程序化纸面，才让「没有竖线」成为结构性事实。
2. **A2/A3 一个组件改一处**：首页两个分类头与规则页标题栏本来就是同一个 `SectionBanner`，
   顺手把「触顶就 contain」写进组件，避免以后再有人调宽度又踩回来。
3. **B1 presence-gated 白名单**：既满足用户「看到完整卡」，又不破坏 P4 的 256 例逐字段等价。
4. **B3 不改 domain 的 confirm 语义**：`RoomConfirm.twice` 依然要 `INTENT.CONFIRM` 才执行，
   修的是「UI 从来没发过那条确认」。这样既有安全语义一点没松。
5. **B4 判据换成「收到过 KICK」**：唯一在收件人视角下成立的硬信号。
6. **B5 真做控制层而不是放个假入口**：服务端协议与本地帧**同构**（载荷不透明透传），
   所以是真能连的；连不上也会如实报错。
7. **C1/C2 不新增写盘口**：复用 `RoomController.writeCard`（K11/C5 唯一路径），
   `await repo.save(` 命中数本轮 **0 新增**。
