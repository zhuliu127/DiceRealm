【3.1】★ 真差异 #1：consent 的 `check.request` 同意路径（第 2 梯队技术债 8，一并解决）

老 APP `room-model.js:1546-1569`：
  if (req.op === 'check.request') {
    if (p.agree) {
      out = out.concat(this._rollCheckRequest(seat, req));
      var sk = cleanText((req.payload||{}).skill, 20) || '检定';
      return out.concat(this._settleRequest(seat, req.id, true, '同意并完成了「'+sk+'」检定'));
    }
    return out.concat(this._settleRequest(seat, req.id, false, '忽略了检定请求'));
  }
老 APP `:3106-3131 _rollCheckRequest`：目标值优先级 ① 角色卡权威技能值
（`_skillBaseOf`）→ ② 请求载荷 base → ③ 100；难度取请求载荷；结果
`diceRoll` → PUBLIC 广播全员。注释明写这是 v2.1.0 修的用户报障
「要求检定点了同意没反应」。

改前新工程 `room_model_host_intent.dart:325-363 consent` **整条分支缺失**：
所有请求都当成状态变更，`list.removeAt(idx)` 后发一句
「KP 调整了 X 的状态」，**没有任何检定结果**；`rollCheckRequest`
（combat.dart 定义）全库零调用点。

修法（`host_intent.dart:340-365`）：照抄老 APP 三段式，
同意 → `rollCheckRequest(seat, req)` + `settleRequest(..., true, '同意并完成了「$sk」检定')`；
拒绝 → `settleRequest(..., false, '忽略了检定请求')`；
**不在分支前先 removeAt**（老 APP 的 `_settleRequest` 负责摘卡并发
REQUEST-done 定向事件，重复删会找不到卡）。难度/base 全取权威请求载荷，
不采信客户端回传。
⇒ 结论：`rollCheckRequest` 选择**接线**而非删除。理由：老 APP 有真实调用链，
删掉是把「死代码」换成「功能缺失」，与「按老 APP 抹平差异」相反。
