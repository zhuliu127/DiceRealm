二、本批挖到一个**真 bug**（生产上会导致「搜到了却连不上」）
----------------------------------------------------------------
现象：服务端启动后 base 是 `http://198.18.0.1:9087`，客户端连它 404。

根因：`resolveIp()` 原来的实现是「拿到第一个非回环 IPv4 就用」。
本机装了 Clash（TUN 模式），`NetworkInterface.list()` 最先返回的是
**198.18.0.1** —— 198.18.0.0/15 是 RFC 2544 基准测试保留段，
Clash/部分 VPN 用它做虚拟网卡。

后果（生产环境同样存在）：
  · 广播出去的是 VPN 虚拟网卡地址，同局域网的同伴**根本连不上**；
  · 而界面会显示「已连接」——用户拿两台手机试半天也搞不清为什么。

修法：改成按「像不像真局域网」打分，0 分不要：
  169.254.*           → 0（链路本地，跨设备不通）
  198.18.* / 198.19.* → 0（基准测试段，VPN TUN 常用）
  192.168.*           → 100
  10.*                → 90
  172.16–31.*         → 80
  其它                → 10
拿不到真私网地址时**宁可留空**（base 退化成 127.0.0.1 + wifi:false），
让界面如实提示「这间房只有你自己能进」，而不是假装连上了。

★ 这条正是旧版 room-lan.js 注释里写过的坑（v1.18.4 修过一次），
  Dart 侧换个形式又踩了一遍 —— 说明「wifi:false 必须提前提示」
  不是可选优化，是必需行为。

三、旧版三个坑的落实
----------------------------------------------------------------
1. **wifi:false 提前提示**
   `LanServerStart.wifi` 由「是否拿到真私网地址」决定；`LanRoomHost.wifi`
   直接透出；`RoomAnnounce.wifi` 随广播发出去。
   ⇒ 界面可以在**建房之前**就说「没连 WiFi，这间房别人进不来」。
   ⇒ 测试覆盖：`RoomAnnounce` 编解码保持 wifi=false；缺字段（旧版本）按 true。

2. **discover 超时兜底**
   `LanDiscoverer.scan()` 用 `Future.any([delay(timeout), done])`，
   到点必返回、必不抛。测试断言：无广播时 300ms 超时、总耗时 < 2s。
   ⇒ 界面不会一直转圈。

3. **injected 残留**
   `RoomEndpoint.candidates()` 的优先级写死：注入的 > 用户手填 > 预设，
   且注入的排第一。测试断言 `c.first` 是注入地址。
   ⇒ 「桥说没跑但地址还留着」的问题在 Dart 侧被这条排序规则挡住。

四、多 base 容错（旧版最容易被简化掉的部分）
----------------------------------------------------------------
旧版 room-net.js 有 16 个「地址」导出，本批落了核心 8 个：

normalize        去空白/去尾斜杠/补 http://
looksValid       只认 http(s) 且 host 非空
isPrivateHost    私网/回环/链路本地判断
split            逗号/分号/中文标点/空白拆分
candidates       注入 > 手填 > 预设，去重排序
wsUrlFor         http→ws / https→wss，路径 /ws
hostOf           取 host
isLanOnly        是否只能同局域网访问

**修的一个边界 bug**：`normalize('http://')` 原实现去掉尾斜杠变成 `http:/`，
再被补成 `http://http:/`，host 变成字面量 "http"，于是 `looksValid`
反而判成合法。加了「只有 scheme 没有 host 直接判空」的前置拦截。

为什么这块不能简化成「一个 base 变量」：
  · 一台手机可能同时有 WiFi + 热点 + VPN 三个网卡，只有一个能通；
  · 用户可能手填 `192.168.1.7`（没写 http://）或带尾斜杠；
  · 注入的局域网地址不能被用户设置里的旧地址盖掉。
简化了就是「局域网时通时不通」，而且极难复现。

----------------------------------------------------------------
五、编排门面（为什么值得单独一层）
----------------------------------------------------------------
`LanRoomHost` 把 LanServer + LanBroadcaster + RoomAnnounce 的生命周期收在一起：

  start()  要么服务+广播全成，要么全不成
           **服务起不来就不广播** —— 否则别人搜到一间连不进的房，
           比搜不到更糟（用户会反复点）
  stop()   一定把广播一起停 —— 否则留下「幽灵房」
  port     `servicePort: 0` 时暴露系统分配的真实端口（本机自连/测试用）
  announce 只带公开字段：房号/房名/KP名/人数/状态/地址
           **绝不夹带 members 明细、场景、日志** —— 广播是明文的

测试覆盖：幽灵房（stop 后搜不到）、幂等（重复 start 不换地址、重复 stop 不抛）、
端口占用（第二个起不来且不广播）。
