二、实现（两个新文件 + 两处接线）
---------------------------------------------------------------

### 1. `lib/ui/room/ai_rp_prompt.dart`（纯函数，~170 行）
对应旧版 `room-ui.js:5313 cleanRpText` + `:5328 buildRpMessages`。

`cleanRpText`：剥掉模型爱加的四类包装
  · `RP：` / `rp:` / `角色扮演：` 前缀
  · ``` 代码块围栏（含语言标记）
  · 整段被一对引号包住（「」/ “” / "" / ''），只剥一层，长度不足 3 不剥

`buildRpMessages`：角色底稿 + 场景 + 最近对话 + 想法 → system + user

★ **与旧版的一处刻意差异：上下文用 `state.chats` 而不是 `state.logs`。**
  两条理由：
    1. **K3 红线**：`logs` 的 `p` 可能带明文，拼进 prompt 就等于发给了第三方。
       即使 Q1 已做脱敏，也不该把「脱敏后的日志」当素材外发。
    2. 裁剪口径：玩家视角的 `logs` 与 KP 不一致，`chats` 才是两边都看得见、
       语义也对的「桌上最近发生了什么」。
  这条有专门的测试：造一条带「秘密检定」的 logs，断言 prompt 里搜不到。

其他细节（都照旧版对齐）：
  · 身体状态为「正常」时不啰嗦
  · 场景说明截到 200 字（避免 prompt 被一段描述吃满）
  · 最近对话取尾部 5 条，过短的（≤2 字）过滤
  · 全程用 `roomText` 不用 `jsStr` —— sheet 里 `name`/`body` 允许为 null，
    用 `jsStr` 会让 prompt 里出现字面量 `null`，模型会照着写出来

### 2. `lib/ui/room/sheets/sheet_ai_rp.dart`（弹层，~230 行）
· 输入想法 → 生成 → `onFilled(text)` + 关弹层
· 参数与旧版一致：**temperature 0.85 / maxTokens 1200 / timeout 60s**
  （RP 比车卡 0.9 稍稳，长度与超时也是按 RP 调的）
· AI 未配置 → 直接说「还没填写 XXX，请先到设置里配置」，不是笼统「生成失败」
· 模型返回空内容 → 报「空内容」，**不回填空串**
  （空串回填等于把玩家已经打好的字清掉）
· 生成中按钮禁用并显示「生成中…」（防连点烧 token）
· 支持注入 `AiClient`（测试用）；生产从 `SettingsScope` 现建，
  `configProvider` 每次调用现读设置 → 改完 Key 立刻生效

### 3. 接线
· `gp_feeds.dart` 的 `ChatInputRow`：在发送按钮**前**加 ✨（`GpFeedsKeys.aiRp`）
  - 位置按 PRD `:307`「入口在聊天输入行」
  - **旁观者不渲染**（既不发言也不用 AI 写发言）
  - `onFilled` 只做三件事：填文本、光标移到末尾、同步 `local.chatDraft`
· `sheet_misc.dart`：AI RP 占位从「下一期提供」改成
  「已可用：在聊天输入行点 ✨」+ 一行独立说明
  —— **不留假入口**（弹层里跳不过去，放可点按钮只会让人点了没反应）

  打开即有「不会自动发送」明示 / 空输入只提示不打网络 /
  **★★ 生成成功 → 回填 + 关弹层 + 零发包** /

其中「零发包」那条的方法：`onFilled` 捕获文本后断言 `f.sent.length` 未变。
这是 PRD P1-12「不自动发送」的唯一证伪点 —— 模型输出可能 OOC、
可能替 KP 宣布了裁定，自动发出去就等于替玩家做了发言决定，
而且已经进了所有人可见的 chats。

四、门禁抓到一处我自己的错
---------------------------------------------------------------
首轮全量 `+1421 -1`，红的是 `jsStr 预算`：
  `sheet_ai_rp.dart:160  if (jsStr(asMap(m)['seat']) == seat)`

我写弹层时顺手用了 `jsStr` 读 seat。**修法不是加白名单**——
这是 UI 层取值，本就该用 `roomText`（`null` → 空串）。
用 `jsStr` 反而有害：它会给字面量 `'null'`，理论上能误匹配一个叫 `null` 的座位。
改成 `roomText` 后门禁自己就绿了。

> 白名单是「审计过的例外」，不该用来盖住「本来就不该这么写」的地方。
