三、parseJson 鲁棒性矩阵（输入形态 → 行为）
--------------------------------------------------------------------------------
实现：lib/domain/ai_gen.dart:177-257；fixture：tool/oracle/dump_ai_fixtures.js
      :190-210（TEXTS 15 例）；断言：test/ai_gen_test.dart:40-101。

逐级抢救（从宽到严，共 4 级）
  ① 去掉 ``` / ```json 围栏（大小写不敏感）→ 直接 jsonDecode
  ② 从第一个 '{' 起配平花括号（跳过字符串与转义）→ 抠出片段 decode
  ③ 去掉尾随逗号 `,\s*([}\]])` → 再 decode
  ④ 仍失败 → 抛 AiGenException，消息带上下文、可直接展示给玩家

| 输入形态                                        | 行为 |
|-------------------------------------------------|------|
| `{"a":1}` 干净 JSON                             | ① 直接 decode → Map |
| ` ```json\n{"a":1}\n``` ` / ` ```\n{...}\n``` ` | 剥离围栏 → ① decode → Map |
| `{"a":1}\n``` `（只有尾围栏）                   | 剥离尾围栏 → ① decode → Map |
| `好的，这是结果：\n{"a":1}\n希望你喜欢`（前后废话）| ① 失败 → ② 抠首个配平对象 → Map |
| `前言 {"a":1} 中间 {"b":2} 尾巴`                | ② 只抠**第一个**配平对象，忽略后续（与旧版一致） |
| `{"a":1,}` 尾随逗号                             | ①/② 失败 → ③ 去逗号 → Map |
| `{"a":1` 截断不闭合（max_tokens 用尽）          | ② 配平失败 → AiGenException「模型返回的 JSON 不完整（花括号没配平，末尾停在：…）」；上层据此判 truncated 并加大额度重发 |
| `{'a':1}` 单引号                                | **刻意不修** → AiGenException「JSON 格式有误：…」（不猜模型想写什么） |
| `完全没有 JSON 的回复` / 空串 / null / 非字符串 | 无 '{' → AiGenException「模型没有返回 JSON 结构（回复开头是：…）」 |
| `{"s":"a}b{c"}` / `{"s":"带\"引号\"的字符串"}`  | ② 配平跳过字符串 + 转义 → 正确抠出，不误判 |
| `{"a":{"b":[1,2,{"c":"}"}]}}` 深层嵌套          | ② 完整配平 → Map |
| `[1,2,3]` / `null` / `42` 数组 / null / 标量    | **不抛，原样返回**（返回什么就是什么），由 toProfile 兜成空 profile → 规则引擎照样出合法卡 |
| `''`（empty string）                            | 无 '{' → 「模型没有返回 JSON 结构」 |

刻意不做的四件事（ai_gen.dart:170-175）
  · 不修单引号 / 不补括号 —— 猜错会把「缺失字段」变成「错误字段」，比失败更糟；
  · 不吞异常 —— 调用方要靠「截断 vs 格式错」决定重试策略；
  · 不把数组 / 数字当卡 —— 由 toProfile 兜底；
  · 不在解析层落地任何数值 —— 那是规则引擎的活（见 §二）。

上层（lib/net/ai_create.dart:96-139）据此决策
  finish_reason=length 或解析失败 → onStage 提示 → 6000 → 16000 重发一次；
  两次都截断 → AiException(emptyContent)「换非推理型模型 / 把描述写短」；
  两次都格式错 → AiException(badResponse)「点重新生成再试」；
  第一次格式错、第二次正常 → 直接成功（不把用户卡在重试里）。

| 本机存储 | localStorage `coc7_card_shares_v1` → `{[charId]: {id,url,delToken,at,name}}` | `<文档目录>/dice_realm/shares.json` → `{"format":"dice-realm.shares","version":1,"shares":{"<charId>":{…}}}`；文件 + 内存双后端；坏 JSON / 空文件 / 无 shares 包一层都容错成空表 |
| 未配置 | `Promise.reject(new Error('UNCONFIGURED'))`（字符串哨兵） | `ShareException(unconfigured, '还没配置分享服务地址')` **不发请求**；UI 未配置时根本不摆上传按钮（只给「怎么开启」+「不开也能用」两条路） |
| 错误分类 | 裸 Error + 字符串哨兵（UNCONFIGURED / 文案） | `ShareErrorKind` 五分类：unconfigured / noRecord / unreachable / http / badResponse；`shareErrorFrom()` 兜住非 ShareException 的异常 |
| delToken | 存 localStorage，随 `list()` 暴露 | 三铁律：只落本机 shares.json / 不上传 / 不进导出 / 不进日志（`ShareRecord.describe()` 只给 id+url）；有测试钉住「请求体里不含 aiKey」「describe 不含口令原文」 |
| 复制 / 打开 | AndroidBridge 原生桥 → navigator.clipboard → legacyCopy textarea；`global.open(url,'_blank')` | 剪贴板 API + `share_plus` 系统分享面板（可选浏览器/微信/邮件），不引 url_launcher / 不配 Android queries |
| 超时 | fetch 默认（无显式） | 分享 30s；AI chat 180s（推理模型慢，90s 会误杀） |

结论：**路由、方法、请求体、响应体、payload 键名与旧版逐字一致**，自建后端
不需要任何改动；差异都在「本机存储位置 / 错误分类 / 权限边界 / 平台桥」这些
客户端内部实现上。
