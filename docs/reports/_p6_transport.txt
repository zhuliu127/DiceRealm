二、设计：和本机环回**一模一样**，只是中间换成 socket
----------------------------------------------------------------
   LocalLoopback（P5）                Remote（P6）
   ───────────────────────────────────────────────────────
   host.intent() → List<SendPlan>     host.intent() → List<SendPlan>
   pumpPlans() 直接喂 client.receive  pump() 序列化成帧发出去
                                     ↓ WebSocket
                                     client.receive() 同一条路径

所以 `room-lan.js` 那句「局域网不是另一条链路」在 Dart 侧**真的成立**：
UI 拿到的还是 `RoomSession`，它不知道自己跑在本机还是网络上。

三条刻意的差异（写进代码注释了）：
  · `hostRead` 恒 null —— 玩家/旁观没有权威只读面；
  · `exportSave` null / `importSave` no-op —— 存档是 KP 的事；
  · `rollback` 返回「什么都没回退」的结果，而不是抛异常 ——
    UI 永不提供回退入口（K1），但诊断路径上不该把页面打崩。

三、协议
----------------------------------------------------------------
7 种帧，刻意做小：
  hello   C→S  我要进房（code / seat / role）
  joined  S→C  进来了（seat / code / role / lastSeq）
  plan    S→C  一条出站计划（`SendPlan.toJson()` 原样）
  intent  C→S  发 INTENT
  act     C→S  发 ACTION（外层 act、内层 p['op']，与环回同形状）
  sync    C→S  补拉
  bye     双向  断开 / 被踢
  error   S→C  出错（只带 code，**不夹带**任何房间状态）

HTTP 侧（同端口）：
  GET /health  房间摘要（不泄漏 playerView 之外的任何东西）
  GET /state?seat=p1  按 seat 裁剪后的全量

★ K3 红线已守：只用 `SendPlan.toJson()`（`plan()` 已裁剪的出站信封），
  全库零处 `LogRecord.toWireJson()`。

四、这一批踩到的三个坑（都写进注释了）
----------------------------------------------------------------
1. **join 后不是「一帧」而是「两帧」**
   服务端 joined 之后紧接一条 plan(sync)。测试里 `connect()` 一返回就断言
   `lastSeq`，结果读到 0 —— 不是代码错，是**测试断太早**。
   ⇒ 教训：握手完成 ≠ 数据就绪，网络测试必须等条件而不是等函数返回。

2. **失败时调 `dispose()` 会让重连永久失效**
   最初 `connect()` 失败分支 `await dispose()`，而 dispose 会置 `_disposed=true`，
   于是 `_scheduleRetry` 再也连不上（静默死掉，无任何日志）。
   ⇒ 拆成 `_closeSocket()`（只关连接）与 `dispose()`（终态）。

3. **握手 waiter 必须「先挂再发」**
   先 `ws.add(hello)` 再 `await _awaitJoined()` 存在事件循环间隙，
   服务端回得快时 joined 会丢失 → 只能等 6s 超时。
   ⇒ 改成先建 Completer 再发 hello。

另外：`_sendFrame` 原来 `catch(_)` 静默吞异常，导致「帧永远发不出去而调用方
毫无察觉」——本机就是靠把它改成打印才定位到问题。现在保留打印。

五、测试（7 条，全绿）
----------------------------------------------------------------
帧协议（纯函数，3 条）
  · 编解码往返：字段不丢、版本带上
  · 坏帧（null / 字符串 / 空 Map / 空 k）返回 null 而不是抛
  · 版本不匹配判不兼容；缺 v 视为兼容（不踢旧客户端）

端到端（真 socket，4 条）
  · 服务端起得来 → 客户端接入 → 收全量 → 发 intent 改权威态（seq 前进）
  · 不存在的座位被拒（UNKNOWN_SEAT，不能凭空造座位）
  · 房号不对被拒（WRONG_CODE）
  · 两个客户端并存；同 seat 重连**顶掉**旧连接而不是新增（peerCount 不变）

★ 这些测试不用 mock：真的开 HttpServer、真的连 WebSocket。
  传输层最容易出的问题是「编译过、跑不通」，只有真跑才抓得到。
